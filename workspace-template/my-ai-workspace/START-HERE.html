Build your next workflow at home

You've done this once in the room. Here's the same path to build any new workflow on your own: pick it, plan it, test it on made-up examples, build it, try to break it, run it for real, and hand it over. Allow about three hours. It splits neatly into two sittings, after step 3.

Same folder: my-ai-workspace in the Code tabMade-up data first, real data lastDrafts only. You press sendStuck? Rewind, or ask "what went wrong?"

The steps

0

Get set5 min

Every build starts from a clean desk.

Do this

  • Open the Claude app → Code tab → your my-ai-workspace folder
  • Start a new session, or type /clear
  • Set the mode to Manual while you build, so it asks before every change
  • Run /workspace-check

You get

A green and amber list. Anything red, fix first: it tells you how.

Watch for

If your prices or services have changed since the workshop, run /business-dna-interview on the file that changed before you build anything new.

1

Pick it20 min

Choose the job worth automating next.

Do this

  • Run /opportunity-mapper, or open workflows/opportunity-map.md and take the next idea on your list
  • Or pick an idea from a card on the first page
  • Write one sentence: "When X arrives, produce Y, and I approve it."

You get

workflows/opportunity-map-2.md (it never overwrites your first map) and your one-sentence scope.

Watch for

Use your real hours, not the guess it offers. The ranking is only as good as your numbers. Start small: two or three steps, one input, one output.

2

Plan it30 min

Design it before anything gets built.

Do this

  • Switch the mode to Plan
  • Run /workflow-blueprint followed by your scope sentence
  • Answer its questions. Edit the plan until it matches how you really work, then approve it

You get

workflows/<name>/blueprint.md: the steps, inputs, outputs, rules and the points where it stops for you.

Watch for

Say how the input really reaches you (a phone call, an email, a form), not how it would be tidiest. If it says it works best in Plan mode, switch modes and ask again.

3

Make test data20 min

Test on made-up examples before anything real.

Do this

  • Switch back to Manual
  • Run /sample-data-maker
  • Open the samples and read them
  • Then ask: "Walk the blueprint through each sample. Don't build anything yet." Add every gap it finds to the blueprint

You get

Five realistic examples in sandbox/<name>/, one deliberately messy, and a better blueprint.

Watch for

This is where the real design happens: missing information, odd formats, sensitive cases. Good place to stop for the day. Next time, start again at step 0.

4

Build it20 min

Turn the blueprint into a working workflow.

Do this

  • Run /skill-builder on your blueprint
  • Read the new workflow in the changes view, then accept it
  • Run /<name> on one sample. Fix one thing, run it again

You get

.claude/skills/<name>/SKILL.md: a plain-English file you can read and edit, plus workflows/<name>/build-log.md.

Watch for

Lots of permission prompts? Once you trust what it's doing, switch to Auto. Don't like a change? Rewind it.

5

Try to break it20 min

Find the edge cases before your customers do.

Do this

  • Run /test-pack
  • Read test-log.md, especially the failures
  • Fix each one, run the tests again
  • Add one rule: "If this is missing, ask me."

You get

Eight test cases in workflows/<name>/tests/ and a pass or fail log you can show someone.

Watch for

The AI marks its own homework, so read the outputs yourself. A perfect score first time usually means the tests were too easy: ask for harder ones.

6

Run it for real15 min

One real item, with you watching every step.

Do this

  • Pick one real input. Take out anything sensitive you don't need
  • If it needs your email or files: + → Connectors, then run /lock-the-doors so nothing can be sent or deleted through it. Test the lock
  • Run it, approve each step, and read what it touched

You get

One real draft in outputs/ or your connected drafts folder. Nothing sent.

Watch for

Check the [CHECK] items and the "Check before you use" box every time. If it gets a fact wrong, fix the Business DNA, not just the draft.

7

Hand it over15 min

Make it a business system, not a one-off.

Do this

  • Run /go-live-runbook
  • Name the owner, the backup, when it runs and the weekly check
  • Write down hours a week now, and what you expect

You get

workflows/<name>/RUNBOOK.md: what it does, who owns it, how to check it, how to switch it off, and a 30-day measure.

Watch for

Put the 30-day check in your calendar now. Hours stay "expected" until you've measured them.

After it's live

Keep it healthy

  • Weekly: look at three outputs. Same mistake twice? Fix the source
  • Run /dna-check on anything that sounds off-brand
  • Prices or services changed: /business-dna-interview on that file
  • Something broke: /workspace-check

Keep it safe

  • Drafts only. You press send
  • Manual while you build; Auto for workflows that have passed their tests; never Bypass permissions. Your safety file applies either way
  • Real customer data only once it's tested, and only what it needs
  • Your data is processed by Anthropic under your Claude plan, outside Australia. Regulated industries: check with your adviser first
  • To switch a workflow off, follow its runbook

When to call Corptec

  • You want the same workspace for your team
  • A job is too big for one workflow and needs several chained together
  • You need it connected to more of your systems
  • You have more workflows than you can keep track of
